# Swift Standards

Use this organization when several specifications govern your subject and you want one Swift representation of it. A `swift-*-standard` package here composes them and absorbs their revisions, so code that depends on it doesn't have to change. To use one specification directly, go to its authority's organization below. This is Layer 3 of the [Swift Institute](https://github.com/swift-institute): each specification follows its source document as literally as possible, under its own namespace, such as `RFC_5322` or `ISO_32000`.

## Start here

- [swift-ietf](https://github.com/swift-ietf): IETF RFCs, such as URI, HTTP, email and UUID
- [swift-iso](https://github.com/swift-iso): ISO standards, such as PDF, date and time, and locale
- [swift-w3c](https://github.com/swift-w3c): W3C specifications, such as CSS and SVG
- [swift-whatwg](https://github.com/swift-whatwg): WHATWG standards, such as HTML and URL
- [swift-linux-foundation](https://github.com/swift-linux-foundation): the Linux platform interface and the Model Context Protocol
- [swift-ieee](https://github.com/swift-ieee), [swift-iec](https://github.com/swift-iec), [swift-ecma](https://github.com/swift-ecma), [swift-incits](https://github.com/swift-incits), [swift-arm-ltd](https://github.com/swift-arm-ltd), [swift-intel](https://github.com/swift-intel), [swift-microsoft](https://github.com/swift-microsoft) and [swift-bipm](https://github.com/swift-bipm): the smaller authorities
